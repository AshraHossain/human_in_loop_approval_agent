# Human-in-the-Loop Approval Agent (UV-powered)

Three independent implementations of the *same* Human-in-the-Loop (HITL) approval
pattern — one per LangChain/LangGraph architecture — so they can be compared
side by side.

| Version | Pause mechanism | Entry point |
|---|---|---|
| `agent_executor_version/` | LLM calls the `hitl_check` tool, which returns a status | `main.py:run()` |
| `langgraph_version/` | Conditional edge routes `awaiting_human` → `END` | `graph.py:app` |
| `runnable_pipeline_version/` | `RunnableLambda` returns a status dict; caller re-invokes `resume_pipeline` | `pipeline.py:hitl_pipeline` |

Every version implements the same four-stage contract:

1. **Detect** — scan input for `UNCERTAINTY_MARKERS` (`maybe`, `not sure`, `unclear`, `unknown`, `ambiguous`)
2. **Pause** — emit `HUMAN_APPROVAL_REQUIRED` / stage `awaiting_human`, and stop
3. **Resume** — re-enter with `human_input` in the payload
4. **Audit** — every stage transition returns a `make_audit(...)` dict

## Running it

Each subproject is its own uv workspace, but **all three use package-relative
imports** (`from .audit import ...`). They must be run as modules from *this*
directory — not from inside the subfolder, and not as bare scripts.

```bash
# from this directory (human_in_loop_approval_agent/)
cd agent_executor_version && uv sync && cd ..

# offline self-checks — no API key, no network
uv run --project agent_executor_version      python -m agent_executor_version.main --self-check
uv run --project runnable_pipeline_version   python -m runnable_pipeline_version.pipeline --self-check

# langgraph has no __main__; drive it through its compiled app
uv run --project langgraph_version python -c \
  "from langgraph_version.graph import app; print(app.invoke({'input': 'maybe do X'}))"
```

The `agent_executor` version's live path additionally needs `OPENAI_API_KEY`:

```bash
export OPENAI_API_KEY=sk-...
uv run --project agent_executor_version python -m agent_executor_version.main "maybe ship the release"
```

### Invocations that do *not* work

```bash
uv run main.py                                   # bare script -> ImportError (relative imports)
cd langgraph_version && uv run python -c "from graph import app"   # ImportError, same reason
```

If you see `warning: VIRTUAL_ENV ... does not match the project environment
path`, that's your shell's pyenv, not this repo. It's harmless; `uv` uses the
subproject `.venv` regardless.

## Dependency notes

`AgentExecutor` **left `langchain.agents` in langchain 1.0**. `langchain>=0.2.0`
resolves to 1.4.x today, where `langchain.agents` exports only `create_agent`.
`agent_executor_version` therefore depends on `langchain-classic`, which still
provides `AgentExecutor` and `create_tool_calling_agent`, rather than pinning
the whole project to a 2024-era langchain.

Worth knowing before you extend this: on langchain 1.x, `create_agent` is
LangGraph underneath. The AgentExecutor-vs-LangGraph contrast this repo exists
to demonstrate **no longer exists in current LangChain**. These three variants
are best read as a historical comparison.

## Known sharp edges

**`audit.py` is duplicated in all three, and the signatures differ.**
`agent_executor_version/audit.py` takes `input_summary` and `actions_taken`; the
other two don't. Changing the audit schema means editing three files.

**`make_audit` mints a fresh `request_id` on every call.** Each stage of a single
request therefore gets a *different* ID, so the audit trail cannot be correlated
across stages — the audit requirement is structurally unmet as written. Mint the
ID once per request and thread it through if you build on this.

**`datetime.utcnow()` is deprecated** and returns a naive timestamp, which is
wrong for an audit log. Use `datetime.now(timezone.utc)`.

**Uncertainty detection is a keyword grep, not a confidence estimate.**
`"I am definitely not sure"` and `"the Unknown Pleasures album"` both trip it.
There is no policy tier, so a confident-sounding request for a destructive action
sails straight through.

**No tests.** Each module carries a `--self-check` (assert-based, offline); there
is no `tests/` directory and `make test-all` skips this project entirely, because
`scripts/run-tests.sh` requires a top-level `pyproject.toml` and there isn't one.

## Scaffold history (why things were broken)

This tree was generated by a `scaffold_hitl_repo.py` that wrote every file in a
`FILES` dict with `"w"` — overwriting hand-edited source without warning. It was
run twice with different `FILES` contents, which left
`agent_executor_version/main.py` containing the text of the scaffold script
itself, a duplicated `[project]` table in `langgraph_version/pyproject.toml`, a
duplicated heading and unterminated fence in this README, and stray trailing
lines in both diagrams. **All of those are now repaired.**

The scaffold script itself was removed on 2026-09-18 and is not recoverable from
git — see the warning below. Do not recreate it. If this tree ever needs
regenerating, write a tool that refuses to overwrite existing files.

> **This project is not in git.** `git ls-files` returns zero files, so every
> repair above exists only as untracked working-tree state. Commit it before
> doing anything else.
